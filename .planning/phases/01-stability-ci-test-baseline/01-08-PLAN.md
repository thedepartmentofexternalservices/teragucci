The Plan 08 dataclass fields are `HealthPing.client_state` and `HealthPong.server_state`, which means the CLIENT must own HealthPing and the SERVER must own HealthPong (a message stamped with `X_state` is sent by X). Plan 08 therefore INVERTS the current direction:
- Before: server→HealthPing, client→HealthPong (no FSM state carried)
- After : client→HealthPing(client_state=...), server→HealthPong(server_state=...)

This is not a speculative inversion — it is the only arrangement consistent with the dataclass field semantics. Task 2 performs the swap; integration tests lock it in.
